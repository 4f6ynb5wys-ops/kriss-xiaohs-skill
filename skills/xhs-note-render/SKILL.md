# 小红书图文渲染器

把文案变成整套可发布的图。**你的工作是写 spec.json，不是写绘图代码。**

## 为什么存在

手写渲染脚本的老路子，每篇笔记一个 `gen_noteXX.py`，结果是：版式逐篇漂移、账号没有识别度、改一处设计要改 N 个文件。
本 skill 把设计系统固化在 `scripts/render.py` 里，**逐篇只允许改文案和主题色**。

## 工作流程

1. 读用户的笔记文稿（markdown / 口述 / 已有的 notes/XX.md）
2. 抽成 `spec.json`
3. 跑 `python scripts/render.py spec.json`
4. **先看 `_缩略图对照.png`** —— 手机信息流里就是这个尺寸，读不清就是不合格
5. 把图交给用户，说明每张对应哪一页

## spec.json 格式

```json
{
  "out": "/绝对路径/notes/07_render",
  "theme": "A",
  "seed": 7,
  "brand": {
    "credential": "开书法机构第 8 年 · 1 万个孩子",
    "seal": ["砚山", "先生"]
  },
  "cover": {
    "title": ["握笔姿势", "要不要改"],
    "accent": "？",
    "sub": "网上两种说法打架，我给一个能自己判断的标准",
    "footer": "6 种错误对照 · 建议打印一张贴书桌"
  },
  "pages": [
    {
      "title": "正确握笔的 4 个要点",
      "body": ["① 三指捏笔，中指第一节侧面托住笔杆", "", "② 手离笔尖一寸，约 2~3 厘米"],
      "note": "配套还有三个「一」：眼离书本一尺、胸离桌沿一拳"
    }
  ]
}
```

**字段规则：**

| 字段 | 约束 |
|---|---|
| `theme` | **留空 = `D` 水墨（默认）** · `A` 宣纸留白 · `B` 深墨立牌（树敌/涨粉型，对比最强）· `C` 暖纸 |
| `cover.title` | **最多 2 行，每行最多 6 字**。主题 D 为竖排，每行 4 字最佳 |
| `cover.sub` (D) | 数组，**每行 ≤ 6 字**。过长会 `assert` 报错撞上竖排标题——报错就改文案，不要改渲染器 |
| `cover.accent` | 单个字符（`？` `！`），全图唯一的点缀色。不需要就留空 |
| `cover.sub` | 一句话，**不许重复 title 说过的事** —— 两个钩子位说同一句等于只有一个 |
| `pages[].body` | 数组，空字符串 `""` 代表空行。**一页最多 8 行**，超了就拆页 |
| `pages[].note` | 底部提示条，**最多 2 行**，是这一页的可带走物 |

## 铁律（渲染前逐条检查）

1. **封面和标题不许说同一件事。** 两个钩子位。
2. **一页只讲一件事。** `body` 超过 8 行就拆成两页，不要缩字号。
3. **最后一页必须能让读者说出"我现在＿＿了"。** 只有互动问句不算兑现 —— 问句是索取，可复述短句才是给予。
4. **点缀色面积 < 3%。** `accent` 只在封面出现一次，内页只用于提示条那条 5px 竖线。
5. **验收只看缩略图。** 全尺寸好看不算数。

## 失败处理

- `numpy` 缺失：水墨主题自动回退到 `A`（纯排版）并打印警告。装上 numpy 可恢复
- 字体缺失：脚本会自动回退到 Hiragino Sans GB，但**粗宋才是高级感来源**，回退后要提醒用户
- 文案过长：不要改渲染器去缩字号，**回去改文案**。版式是约束，不是变量
- 用户要求改版式：先问清楚是这一篇的例外还是要改全账号。**例外一律拒绝**，改就改 `render.py` 里的设计系统，全账号一起改
